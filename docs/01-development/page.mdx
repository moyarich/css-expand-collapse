# Development

## Repository structure

```text
css-expand-collapse/
├── apps/
│   └── playground/                  # React + Vite playground
├── docs/
│   └── ...                          # Markdown/MDX documentation
├── packages/
│   ├── css-expand-collapse/         # core npm package
│   └── css-experimental-shorthands/ # optional plugin package
├── README.md                        # canonical package README / single source of truth
└── package.json                     # workspace scripts
```

The workspaces include:

- `packages/css-expand-collapse` — publishable `@moyarich/css-expand-collapse` package.
- `packages/css-experimental-shorthands` — independently publishable optional plugin package.
- `apps/playground` — React + Vite playground for exercising the package against real CSS.

The playground consumes package source directly during development, so the library does not need to be built before starting it.

## Repository setup

```bash
npm ci
npm run dev
```

## Workspace commands

```bash
npm run dev               # Start the playground
npm run generate:registry # Regenerate shorthand registry barrel
npm test                  # Run library tests
npm run typecheck         # Typecheck all workspaces
npm run build             # Build library + playground
npm run build:lib         # Build only the npm package
npm run build:playground  # Build only the playground
npm run pack:lib          # Preview npm package contents
```

The package also exposes `check:registry`; package `test`, `typecheck`, and `build` run that freshness check automatically.

## Package validation

From the repository root:

```bash
npm ci
npm run typecheck
npm test
npm run build:lib
npm run release:check
npm run pack:verify
```

Release validation verifies a real temporary npm archive without publishing. Archive verification checks export targets, required documentation and absence of build source maps, requires the system `tar` command and reports archive size. Consumer installation checks remain separate. See [versioning and releases](../03-releases/page.mdx) for publication commands.

## Experimental companion development

Build the workspaces before checking the public package entry points:

```sh
npm run build
npm run typecheck --workspace @moyarich/css-experimental-shorthands
npm test --workspace @moyarich/css-experimental-shorthands
```

The companion uses the core public API as a peer dependency. Its public exports test imports the built package by name rather than a private source path.

## Benchmarks

Run the opt-in transformation benchmarks with:

```sh
npm run bench --workspace @moyarich/css-expand-collapse
```

See [benchmark methodology](../../packages/css-expand-collapse/bench/CONTRIBUTING.md) for workloads and comparisons.
